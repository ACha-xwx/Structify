# 学习深度与大纲审阅：实施及验收记录

日期：2026-10-18。工作目录：`G:/Code/Structify`。

## 已落地的产品闭环

学生选择快速总览、标准学习或深入掌握，先生成大纲。学生可以连续提出修改意见、切换深度、查看差异、恢复历史版本；恢复会写成新版本。明确确认后才冻结学习路线并准备首单元，已有课堂 URL 继续可读。

正文按“单元规划 → 当前步骤选择材料与讲解 → 结构/授权/教学检查 → 保存检查点 → 单元发布”生成。步骤数随目标展开，每单元最多八步，不再把整堂课压成五步。按步骤挑选相关课件、动画和源码；实现活动必须使用匹配代码，有运行能力且学生确认实验活动时才安排运行实验。课件保留多页与逐页讲解。

失败只影响当前单元。成功步骤保存在内部检查点中，单元整体通过后对外 READY；显式重试复用成功步骤与单元计划。原有合格步骤及材料不会因修复而被删成纯文字。模型检查基于当前子目标，单元目标只是背景，避免误判后要求一小步讲完整个单元。

## 实际技术路径

- `studyroom/draft`：三档类型、大纲结构/范围校验、资源与运行能力检查、版本差异、草稿和审阅对话、确认与恢复接口。
- `studyroom/curriculum/CurriculumCatalog.java`：栈、队列、二叉树的首批知识检查表；总览问题检查缺项，学生可以明确排除。具体应用等窄问题不会被强制扩大为整章。当前仍标识 EVIDENCE_ONLY，不冒充经教师审核的完整课程标准。
- `StudyroomUnitPlanner.java`：在已确认单元内展开子目标，保留所有必要活动；允许概念引入与理解检查，禁止新增未经确认的过程、代码或实验活动。规划结果跨重试复用。
- `StudyroomUnitComposer.java`：逐步绑定材料、提供实际代码原文、定点修复、保存正文检查点；非代码活动不向模型提供代码候选，过程/实验之外的活动不提供动画候选，减少冗余。
- `generation/TeachingQualityGate.java`：根据资料与实际源码检查当前步骤，检查函数名、教学目标、实验任务和观察依据，失败提供具体修复问题；不会仅凭一个分数放行。
- `generation/GenerationCallService.java`：复用现有 AiQuotaExecution；每阶段持久化请求标识与响应，成功响应可以重用，SENT/UNCERTAIN 不自动重复调用。
- `generation/JdbcGenerationRepository.java`、`StudyroomGenerationWorker.java`：数据库队列、120 秒租约、15 秒心跳、每实例最多两个 Worker，用户行锁约束同一用户并发。领取到期时间使用数据库时钟。
- `generation/UnitPublicationService.java`：单元读取、按需准备/重试、首单元完成后至多预取下一单元；发布校验当前 run 与任务租约。目标、材料和上下文哈希相同的已准备内容，重新校验授权后可以复用。
- `frontend/src/user/components/studyroom/StudyroomOutlineFlow.vue`、`StudyroomOutlineView.vue`：问题与三档入口、大纲轮询、修改/差异/历史恢复、明确确认与返回课堂。
- `StudyroomView.vue`：单元与步骤导航、局部准备状态、已确认大纲、重新规划入口；稳定步骤 key 保留代码草稿与资源状态。后台页面将轮询间隔降到十秒。

接口与 DTO 见 `contracts/openapi-v1.yaml`；新增写接口使用业务 `Idempotency-Key`，与请求追踪 ID 分开。同键不同载荷返回 409。读取不触发模型。

## 持久化与兼容决定

新增 Flyway V28 保存草稿、不可变版本、审阅消息、课堂 run、单元、任务、模型调用与业务幂等键。确认事务切换 `current_run_id`；旧步骤、旧进度和迟到对话不能写入新路线。旧数据的 run 字段为 NULL，原课堂继续可读。

保留原有 `(study_room_id, step_order)` 唯一约束，采用 `runRevision * 10000 + unitOrder * 100 + stepIndex` 分配新步骤序号，同时增加 `(unit_id, step_key_in_unit)` 唯一约束。这替代计划中跨数据库删除旧约束的方案，避免 MySQL/H2 约束语法差异；对外仍按单元与步骤展示。

实际状态名为 GENERATING / REVIEWABLE / FAILED / CONFIRMED；单元未请求状态为 PENDING；材料可用性为 AVAILABLE / UNAVAILABLE / UNVERIFIED。单元活动可继续细分为多个同类步骤，并辅以概念与检查，不能借此新增未经确认的运行实验。一个材料类型允许多个用途，最多三项用途、三种材料类型。

原创建课堂 POST 返回 STUDYROOM_OUTLINE_REQUIRED，不能绕过审阅直接生成正文。原课堂读取、进度和正常追问保留；新路线的扩充需求引导回大纲审阅。

修改失败会回到上一有效版本和对应深度；显式重试仍保留失败请求的目标深度。JSON 仅允许剥离完整对象外的围栏或多余闭合括号，不截断、补写或丢弃教学内容；第二个对象或不完整 JSON 会被拒绝并定点修复。
