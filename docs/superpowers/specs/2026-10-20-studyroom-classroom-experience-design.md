# 课程问答：连续课堂、增量大纲与等待动效

## 决策与范围

用户已在本次对话中确认主流程与实现边界：沿用 Structify 视觉，采用阶段动画与真实大纲增量，完整校验后确认；课堂以材料为中心，提问带上下文，回答流式呈现并可恢复原位置。用户另确认将受控教学动作和知识点小练习纳入同一实施计划，按先后顺序交付。

本文件记录已确认的设计，尚需用户审阅书面版本。它不是实现完成声明。

### 依据与现状

- `docs/architecture/studyroom.md` 和 2026-10-18 progressive-studyroom 设计仍规定资源权限、冻结片段、预算、验证发布、租约、幂等和额度记账边界。
- 当前工作树已有未提交的片段实现、课程库及相关测试。架构状态说明尚未同步全部工作树进展；实施前必须核对实际调用链，不能把设计或测试记录当作生产功能完成证明。
- `StudyroomOutlineFlow.vue` 当前通过轮询取得完整大纲；`OutlineModelGateway` 通过完整模型响应规划大纲。现有等待主要是文字状态，需要真实增量通道，而不是将完整结果延迟拆开播放。
- `StudyroomView.vue` 当前把知识点、材料和追问纵向排列，追问等待完整响应；已有场景、资源、代码运行结果上下文，以及学习位置和代码草稿保留的基础。
- 本地 OpenMAIC 参考：generation-preview 使用阶段动效、SSE 大纲条目及可展开审阅；PlaybackEngine 管理讲授与讨论切换；SceneRenderer 在同一舞台显示多种内容。人工示例和一次真实问答不代表其自动生成课程质量已验证。

### 采用的方案

讨论过仅阶段动画、仅逐项生成，以及两者结合。采用组合方案：阶段反馈说明正在做什么，已接收到的条目展示实际产出；校验完成才允许确认。它同时改善等待反馈和可读性，需要改造后端事件交付。

仅阶段动画实现较轻，但不能让学生提前查看真实产出；仅条目列表在首个条目到来前仍缺少反馈。组合方案不显示估计百分比或虚构剩余时间。

### 交付顺序

1. 连续课堂基础：真实增量大纲与候课动效、材料主舞台、常驻提问、引用提示、流式回答、位置恢复。
2. 基于同一课堂状态补齐受控高亮、动画步骤，以及知识点小练习。

第二部分是本次范围，不是被移除的后续愿望。两部分共用身份、事件和课堂状态，实施计划按依赖顺序拆任务。

不包含多人角色编排、自动生成整套新课件、付费语音服务接入或通用白板编辑器。已有课件、动画、C 代码能力继续复用；Node 兼容服务及其他产品模块保留。

## 用户主流程与布局

### 大纲生成与审阅

1. 学生提交问题和学习深度，立即显示提交反馈。成功创建任务后转入该草稿的生成状态。
2. 展示服务端真实阶段：排队、检索授权资料、规划大纲、检查大纲；未提供更细阶段时使用“正在规划大纲”，不能按时间自行切换文案。
3. 每收到一个完整条目，列表追加该条目并以短淡入展示。用户可以展开列表查看标题、目标和材料计划。流中条目只读，并注明“生成中，尚未确认”。
4. 已通过校验的大纲替换预览并开放审阅、修改和确认。确认必须携带现有 revision、planHash 和幂等键，不能确认增量缓冲区。
5. 修订生成时保留上一个有效版本，清楚区分“当前已保存版本”和“正在生成的新版本”。流失败时保留有效版本，未验证预览不成为新版本。

不模拟逐字生成，不暴露模型思维链，不按固定时间填充进度条。

### 确认后的候课

显示已确认课程标题、首个知识点及首段准备状态，复用阶段动画组件。事件只能反映已发生的资源准备、内容生成、验证和发布状态；暂未开始的阶段不能标成完成。

首段有效发布后即可进入课堂，后续片段依照既有有界准备规则继续。用户仍停留在对应草稿、revision 和 run 时才自动进入；离开页面、切换任务或生成路线已更新时不得跳回。读取状态失败提供重连，内容准备失败提供明确进入课堂和重试入口，不丢失已发布内容。

### 课堂主舞台

- 桌面：顶部课程与知识点位置，左侧可收起的单一知识点路线，中间材料主舞台，右侧可收起的问答面板。问答关闭后有常显的文字提问入口。
- 材料主舞台承载当前片段的主要材料，切换现有课件、动画和代码场景；讲解文字作为与材料配套的可展开内容。避免同一屏重复渲染主导航。
- 平板：路线折叠为目录入口，材料与问答按宽度选择并排或覆盖面板。
- 手机：材料全宽，目录与问答通过独立面板进入；提问面板位于底部并适应软键盘，不把大段问答永久堆在材料下方。
- 保留现有 UI 字体、AI 球、玻璃表面、胶囊控件与主题 token。动效不改变已确认的视觉语言。

### 提问与恢复

提问入口始终可见，快捷键仅作补充。输入框上方显示可移除的引用提示，例如“栈的基本操作 · 课件第 2 页”或“顺序栈 · 第 12–18 行”。没有选区时使用当前知识点和材料；不虚构引用。

提交问题时冻结本次引用与学习快照并暂停自动播放。回答流式展示在问答面板中，材料仍可查看。学生可手动换材料，但不能因此改变已发送问题的上下文。

回答完成或显式停止后显示“继续刚才的讲解”。点击后恢复快照中的材料与位置；只有此前正在播放的动画才恢复播放，原本暂停或手动阅读的内容保持暂停。切换知识点、run 更新或资源修订发生冲突时，按钮解释当前位置已变化，并提供返回来源入口，不覆盖学生的新选择。

## 前端职责与状态

### 组件边界

- 大纲生成控制器：管理草稿身份、预览、校验完成版本和事件订阅。
- 通用生成反馈组件：只接收真实 phase、状态、可选条目和错误，渲染阶段动画、骨架及完成过渡；不负责网络请求或推断任务完成。
- 课堂布局：组织目录、材料和问答，不直接驱动模型。
- 课堂会话控制器：统一管理阅读、提问、回答、等待恢复以及异步请求失效。
- 材料适配器：分别暴露课件页、动画位置与播放状态、代码草稿/标准输入的快照与恢复；不依靠卸载重建恢复状态。
- 问答面板：呈现引用、流式文本、等待、失败与停止操作。
- 教学动作执行器与练习面板：分别处理通过校验的非破坏性动作和知识检查。

快照身份包括 roomId、runId、知识点 ID、fragmentId、内容修订、sceneId、resourceId 与本地导航版本。材料数据包括课件页 ID、动画位置/速度/播放状态、代码草稿与标准输入。草稿沿用现有本地保留机制，不因快照新增将完整学生代码上传模型的行为。

问答状态为 READING、ASKING、ANSWERING、AWAITING_RESUME；生成状态和学生学习进度独立。显示面板不改变服务器确认版本，完成准备不等于学生完成学习。

## 后端真实事件与模型边界

### 事件来源

在现有生成任务与额度执行通道上增加流式能力。不得绕开 AiQuotaExecution、GenerationCallService 的调用记录、幂等与预算，也不得为每个订阅者重新调用模型。

大纲只从真实模型增量中提取已闭合、可解析的完整单元对象。解析器须处理跨 chunk 的字符串、转义和嵌套 JSON；不展示任意不完整 JSON，不通过补字修复制造已生成条目。预览只允许预期文本字段与材料计划，不包含执行权限或可执行 HTML。

完整模型响应仍进入现有授权证据、schema、教学范围、资源可行性和计划校验。通过后才创建新 revision 并发布正式可确认事件。预览先到不改变发布权。废弃任务或已失效租约的增量不得写入当前预览。

### 持久事件与重连

采用持久任务事件与快照，SSE 仅为传输。事件包含事件序号、实体身份、任务 ID、attempt、run/revision、事件种类及必要载荷；服务端分配单调递增序号。任务重试创建新的 attempt，客户端清除该 attempt 之前的未验证预览，保留已确认版本。

事件种类包括 phase、outline_item、outline_validated、content_published、answer_delta、answer_completed、failed、cancelled 和 reset。大纲条目最多 24 个，单条预览最多 16 KiB；回答增量适度合并后落盘，避免逐 token 建一行记录。文本总量及模型调用仍受现有配置上限约束。

订阅通过已有带凭据的 fetch/SSE 客户端连接，使用 since 游标；连接建立和重连时校验当前用户、实体所有权及是否删除。若游标过期，返回 reset 和当前权威快照。终态任务事件保留 24 小时，清理后仍可读取保存结果；活动任务不得仅因事件保留期到期而失去恢复能力。

浏览器重连仅恢复订阅，不重发生成、确认或提问。离开页面停止订阅，后台有界任务继续；显式停止问答才发送取消命令。取消会阻止后续消息和动作发布，已消耗 token 依现有规则结算，不重置账本。

### 接口演进

- 保留现有大纲创建、读取、修订、恢复和确认接口。读取补充当前任务快照、真实 phase、attempt、预览条目和事件游标；新增 `GET /study-outlines/{id}/events`。
- 保留既有 run 读取接口；新增 `GET /studyroom-runs/{id}/events`，发布事件只提示有已验证内容可读，客户端从权威读模型恢复。
- 当前课堂 `POST /study-rooms/{id}/messages` 演进为带 Idempotency-Key 的异步提问，返回 202、questionId 和初始状态。请求保留 question/context，并增加来源 run、内容修订和引用快照身份。
- 新增对应问题的 GET 快照、GET events 和 POST cancel：`/study-rooms/{id}/messages/{questionId}`、其 `/events` 与 `/cancel`。
- 迁移本模块所有调用方、类型、契约与测试后替换原同步交付行为；不另建第二套模型生成链，也不改动其他模块的聊天接口。

问题在服务端接受时记录唯一用户消息。流中回答保存在问题状态，完成后一次提交正式助手消息；重连和幂等重试不得重复消息。失败可保留标注为未完成的回答供查看，但不将其伪装成完整回复。明确重试创建新尝试，界面提示可能消耗额度。

每个用户的当前 run 同时只允许一个活动课堂问题。重复幂等键与相同请求返回同一个 questionId；相同键而内容不同则返回冲突。用户明确停止或前次问题进入终态后才可提交下一个问题，避免回答来源与恢复位置互相覆盖。

以上具体字段在实施计划中与当前运行代码核对并写入 OpenAPI；接口语义以本节为约束。

## 受控教学动作

本次只支持三类动作：高亮已授权代码行、突出已绑定材料元素、推进已绑定动画的合法步骤。它们使用当前资源 ID、合法目标和有界参数，不接受脚本、任意资源链接、浏览器求值或未校验的模型工具调用。

动作需携带 run、片段内容修订和顺序号。服务器校验后才交付执行；同一序号重复到达不得重复推进。目标不可用、当前材料已切换或修订不匹配时跳过并保留文字说明，不自动跳转或执行未知内容。学生可以关闭动作效果。

每次讲解或回答最多接受 20 个动作。代码行必须落在已授权源码范围，材料元素必须存在于当前绑定资源，动画步号必须落在材料适配器声明的合法范围；越界动作不执行。

动作只在材料适配器已声明支持时执行。没有节点级目标或可靠步进接口的材料使用文字说明，不假装高亮成功。读取位置、权限、资源绑定和发布始终由服务端控制。

## 知识点小练习

每个知识点完成讲解后提供 1–3 道单选预测/理解题。题目随现有有界片段生成与校验通道产生并保存，不另起无预算的生成链。初期不加入模型评分的开放问答题。

题目、选项、正确答案和解析需通过结构、教学范围与内容校验；正式题目绑定 run、知识点及内容修订。前端作答前不取得正确答案，提交由服务端判定并保存可幂等的作答记录；结果页显示解析，允许明确重新作答并保留尝试记录。

通过知识点练习读取接口和带幂等键的作答接口交付：`GET /studyroom-runs/{runId}/knowledge-points/{unitId}/checks` 与 `POST /studyroom-runs/{runId}/checks/{checkId}/attempts`。接口必须校验当前用户、当前 run、题目修订与可见性。

练习结果与阅读完成记录分别保存。看过内容、答对一次以及掌握知识点是不同证据；本次不自动修改学习地图的掌握度算法。题目未就绪或校验失败不锁住已发布讲解，也不以“已掌握”代替缺少的练习结果。

正文合格而附带题目未通过检查时，正文按既有规则发布，练习单独记录未就绪或失败；不为了填充题目而无限追加模型调用。显式重新准备练习必须受服务端预算和额度规则约束，已有讲解保持可读。

## 动效、可访问性与异常

生成反馈复用 AI 球的状态和轻量淡入/骨架动效；静态文案始终说明实际状态。减少动态效果时取消旋转、呼吸和位移动画，仍保留阶段、条目和状态提示；减少透明度时使用实色表面。

大纲新条目不强制滚动，不逐 token 打断屏幕阅读器。阶段变化使用克制的状态播报，完成与失败有明确文本。所有核心操作可用键盘完成；面板有标题、可见焦点、关闭入口和焦点返回。手机软键盘不得遮住输入框及发送操作。

断线、超时、失败和取消是不同状态。网络断线不宣称模型失败；失败停止完成动画并显示原因。生成失败保留上个正式 revision，片段失败保留其他已发布内容，问答失败保留学生输入与来源。旧事件、旧请求和删除课程的迟到结果不得重新进入当前界面。

## 数据变更与验收

使用唯一版本的向前 Flyway 迁移增加任务事件、问答状态/草稿、教学动作及练习记录所需存储；实施前检查当前迁移最高版本，不预占与其他在途工作相同的版本号。不启动第二个进程访问同一个 H2 文件，不重置数据库。

验证使用合成数据及可控流式模型夹具，不调用付费模型。必要的演示调用与普通测试明确分开。

必须覆盖：

1. 跨 chunk 大纲解析、条目去重、完整校验前禁止确认、修订失败保留旧版、重试清理旧 attempt 预览。
2. 事件所有权、删除后拒绝访问、断线续读、游标过期 reset、多个订阅不增加模型调用、额度结算与租约丢失。
3. 首段发布进入、后续失败仍可读、离开草稿不跳回、旧 run 和低版本状态不覆盖当前状态。
4. 问答提交幂等、增量顺序、取消后迟到事件、单次正式消息提交、来源修订变动处理。
5. 提问前后恢复课件页、动画状态和代码草稿；手动切换后不强制回退。
6. 动作目标与参数校验、重复动作不重复推进、不可用目标的文字回退。
7. 练习未就绪状态、判分、重复提交、跨用户访问、旧题目修订和作答记录独立于阅读完成。
8. 桌面、手机、长大纲、软键盘、减少动态效果、减少透明度及键盘操作。

通过仓库统一验证入口运行对应 backend、frontend、contracts、architecture 和 e2e 范围，并运行验证器自身测试。原有相关回归仍需通过，未实现检查不得报成功。

## 书面设计自查

- 范围涵盖已确认的生成反馈、连续课堂、真实流式回答、动作和练习；交付顺序明确。
- 未验证预览与正式 revision、准备完成与学生学习进度、问答中断与网络断线均有独立语义。
- 每个异步过程都有身份、失败恢复和旧结果隔离要求；动效没有发布权或预算控制权。
- 无占位需求；缺少材料目标时的回退、旧修订冲突、事件过期和题目未就绪行为均已确定。
