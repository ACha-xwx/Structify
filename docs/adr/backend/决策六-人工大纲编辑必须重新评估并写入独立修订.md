# F. 人工大纲编辑必须重新评估并写入独立修订

## Context（背景）

工作区增加人工编辑入口后，用户输入不能因为来自编辑器就绕过服务端计划约束。基础修订可能过期，确认后计划已用于生成；直接覆盖草稿还会丢失历史。代码证明新增了这些检查，但为何选择当前字段调整范围及永久禁止确认后编辑，待确认。

## Decision（决策）

人工编辑走同步事务而非模型任务。校验所有权、基础修订、生成状态、确认状态和幂等键；保留已有知识点内部属性，对新增知识点使用服务端默认属性。重新执行大纲验证、资源可行性评估和编译检查，插入新 revision 及差异记录后更新 latest_revision。客户端不能直接提交权威资源评估或片段计划。

## Considered Options（考虑过的方案）

未发现当时评估候选方案的记录。事后分析的可能替代方案：直接覆盖最新大纲会失去历史和冲突边界；人工编辑复用模型修订会引入额外模型调用；当前实现选择不调用模型但仍执行服务端确定性校验。不能据此声称团队曾实测过三种方案。

## Consequences（影响与约束）

正面：保留人工修改历史，统一执行前约束，避免重复请求新增多个修订。

代价：同步重新评估带来请求延迟，用户措辞或属性可能受评估结果影响。

新增约束：后续导入和批量编辑也不能绕过修订、确认和所有权规则；契约与编辑 UI 需一致处理冲突。

风险与后续：需确认允许评估器改变的字段、人工意图的保留方式和确认后修改政策。
