# 课程问答调用链排查与验证（2026-10-13）

范围：本地 Vue 开发服务 5173、Spring 主服务 8792、原版 `知识库/` 和 `WebP/`。诊断在独立 8793 服务进行，修复后已切换主服务。未执行线上发布。

## 失败证据

用户问题为“二叉树知识点有哪些？”。扩展复现问题“详细讲解二叉树的全部知识，包含遍历、线索树、课件和动画”在修复前首次生成与修正均失败：模型两次返回 `finish_reason=length`，`completion_tokens=4000` 等于输出预算，JSON 不完整。此前只返回“大纲无效”，没有记录模型结束原因。

## 实际链路

1. Vue `StudyroomView` 经 `userApi.createStudyroom` 发送问题和请求 ID；创建超时 120 秒，追问 60 秒。
2. Spring 验证登录、章节、问题，检索已发布且授权的知识片段；无证据拒绝调用模型。
3. 资源目录收集原版 PPT、确定性动画能力和可用代码。树章节实测有 345 个候选；现在按问题相关性分类型选择最多 12 个 PPT、8 个动画、4 个代码，描述限制 240 字符。模型只能引用本次候选 ID。
4. 配额账本按用户、日期、操作和请求 ID 预留并结算。操作名现在支持下划线，创建、追问、修正不再因非法操作名退化而合并。
5. 模型生成紧凑、分阶段大纲：4–8 步、每步最多一个资源、讲解长度受提示约束；输出预算 6,000 tokens。模型适配器保留结束原因和 token 用量。
6. JSON 校验仍执行字段、步数、ID、证据授权、资源授权和参数限制。截断结果不入库，最多重生成一次更短的大纲；再次截断返回明确错误。
7. 树动画 `initialData` 校验为非空层序数组，允许 `null` 空子结点；拒绝括号树和逗号字符串。JSON 参数解析保留数组中的 null。
8. 通过校验后保存课堂、步骤和对话。恢复时再次检查候选资源是否存在且可用。
9. 前端统一后端小写资源类型与界面大写类型；图片通过受控接口提供原版 WebP；动画调用规划和模拟接口后交给播放器。

## 回归与实测

- 后端相关测试 108 项通过，覆盖大纲解析、候选授权、截断重生成、树参数、配额、模型配置、原版资源导入和保存恢复。
- 前端相关测试 24 项通过，覆盖创建/恢复/追问 API、资源类型规范化、超时配置与自习室组件；前端构建通过。
- 原版资源集成验证：22 个课件、1,210 页，课时与页面绑定正确；第四章、第十章没有用模拟资料补齐。
- 修复后诊断实测：“二叉树知识点有哪些？”约 6.5 秒生成 8 步，恢复后资源全部可用；扩展复现问题约 6.6 秒生成 8 步，正常 `finish_reason=stop`，输出约 1,300 tokens。
- 全部选中 PPT 图片逐一返回 200；先序、中序、线索遍历动画逐一调用规划与模拟，返回动画数据。
- 浏览器主服务实测用户原文：最终版本生成 8 步课堂，实际显示原版二叉树课件；动画“下一步”后当前结点与访问列表同步更新。截图保存于 `private/studyroom-chain-ppt.png` 与 `private/studyroom-chain-animation.png`。
- 追问发现并修复：回答引用的证据子集不能覆盖原检索授权集合；补充资源对象必须明确只允许 type、id、parameters，避免模型多写 title 导致校验失败。补充校验失败时明确告知未添加步骤，不再保存“已追加”的虚假承诺。
- 修复后实际追加先序遍历步骤，课堂从 8 步变成 9 步；新增动画规划与模拟成功，重新读取仍为 9 步。

## 运维边界

## 21:00 后续失败核验

用户以“二叉树有哪些知识点”提交时，21:00 与 21:01 的主服务日志显示 `finish_reason=stop`，输出约 1,300 tokens，未截断。两次均因 `Resource is not in the authorized candidate list` 被拒绝，且修正后仍引用错误资源。因此先前有限的成功请求不能代表生成稳定性；本次不是配额、超时或旧服务导致。

校验错误现在包含具体资源类型和 ID，供修正调用定位。修正后仍无效的资源引用会被删除，相关步骤明确变为文字讲解；合法资源保留。该处理只在完整 JSON 解析与证据授权通过后执行，处理后的结果再次完整校验，不会放行未经授权的证据或伪造资源。

新增回归测试覆盖坏资源降级与证据授权不能被绕过；25 项大纲/资源相关测试通过。主服务实测三次：“二叉树有哪些知识点”两次与“二叉树知识点有哪些？”一次，分别约 10.8、5.8、6.0 秒生成 6、7、8 步，恢复资源不可用数均为 0。第一轮再次发现模型构造了 `ppt:ch08-deck02-0e59a17aeee452e2-s001`，本次详细错误提示使修正成功。

启动使用开发 profile 与原版资源目录。当前 H2 是内存数据库，重启会重建开发数据；线上持久化数据库与模型连接尚未验证。后端日志记录请求 ID、证据数量、候选数量、输入长度、模型耗时、结束原因、校验错误及保存结果，不输出 API 密钥或完整模型内容。
