# E. 将模型输出截断判为失败并保留调用用量

- Status：Accepted
- Date：2026-10-24（补录日期，原始批准日期待确认）
- Related commits / pull requests：8273652；已提交实现，未确认独立 PR 编号。
- Relation：Amends [决策二-智能体执行可靠性与成本控制](决策二-智能体执行可靠性与成本控制.md)；补充其边界，不替代或废止原记录。Proposed 的补充规则尚未获得正式接受。

## Context（背景）

旧路径没有针对 finish_reason=length 统一拒绝成功；有正文的响应可能因达到输出上限而不完整。协议处理需要区别“收到内容”和“完整完成”。截断调用也可能已消费 tokens，业务失败不能被视作零费用。是否曾发生截断内容误发布的线上事故待确认。

## Decision（决策）

同步与流式模型客户端都把 length 结束原因转换为 MODEL_OUTPUT_TRUNCATED。流式处理中累计截断状态及已报告用量，在相关结束路径拒绝按成功返回；异常携带供应商已报告 tokens。后续客户端接入必须保留失败类型和用量语义，不能仅凭非空正文判成功。该规则不自动决定前端是否展示已收到的部分文字。

## Considered Options（考虑过的方案）

旧实现缺少此显式截断分支，新实现拒绝截断成功，这是可确认的行为变化。未发现历史选型比较。事后分析的可能替代方案：保留部分结果并显式标注不完整，或对特定任务执行续写；两者均需要任务级完整性和额外预算规则，不能假定当前已经支持。

## Consequences（影响与约束）

正面：业务层能识别输出上限导致的不完整结果，并保留已报告用量。

代价：即使部分内容可读，调用仍失败；重试可能额外收费，不能把本规则解释为自动重试许可。

新增约束：同步、流式及固定地址客户端保持一致；异常传播和额度结算测试必须覆盖截断。

风险与后续：供应商结束原因兼容性、缺失 usage 的处理和部分内容展示政策仍需确认或验证。
