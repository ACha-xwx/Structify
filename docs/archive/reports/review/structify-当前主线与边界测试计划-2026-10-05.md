## 四、学生边界测试（建议**与批次 1 并行启动**）

### 为什么现在就要开始

我们几个人能想到的 bug 已经列完了；剩下的藏在**真实使用的边角**里（弱网、连点、切页、超长输入、换设备）。学生是最便宜的探针，而且他们的第一批反馈正好能验证批次 1 是否真的把"讲稿对不上"修好了。

### 什么时候开始（建议）

**批次 1 的第 1、2 步上服务器之后立即开始。** 理由：那时的课堂讲稿才值得测；早于这个时间点，测出来的错配我们已知，浪费学生的耐心。

### 分组任务卡（每组 5–8 条，直接发给学生）

**A 组｜课堂（最重要）**
1. 选一节有课件的课，从第 1 步走到最后：**每翻一页，看左边讲的是不是右边屏幕上那一页**；对不上就记下"第几步 + 屏幕页码 + 讲稿头一句"。
2. 故意答错同一个问题 3 次，看系统会不会卡住、会不会自己跳过。
3. 答对后连续点"继续"5 次，看有没有跳页或空屏。
4. 中途退出再进来，看是否接着上次的进度。
5. 手机竖屏 + 横屏各走 5 步，看课件和讲稿是否还对得上。
6. 提问时输入超长一段（比如贴 2000 字），看会不会报错。
7. 在课堂里刷新页面，看会话是否丢了。

**B 组｜动画实验室**
1. 用"一句话"描述 5 个演示（例如：单链表逆置 / 二叉树层序 / 快速排序分区 / 拓扑排序 / 折半查找），记下**系统给的是不是你要的**。
2. 故意跨章节问（例如在"栈与队列"章里问"折半查找"），看它怎么答。
3. 参数给极端值（数组只有 1 个元素、10 个元素倒序、空树），看动画是否合理。
4. 连点"下一步" / 拖进度条 / 频繁切倍速，看会不会错帧或卡死。
5. 观察并回答一个问题：**这个动画你看得懂吗？如果看不懂，是哪一步看不懂？**

**C 组｜聊天（课程问答）**
1. 问一个教材里有答案的问题，点引用看能否定位到资料。
2. 打开"深度思考"，问一个复杂问题，看思考链是否跟回答分开、是否卡住不结束。
3. 上传 1 张图片 + 1 个代码文件（各不超过 8MB），看能否解析。
4. 发一条消息后在生成中点"停止"，再点"重试"，看会不会重复或丢内容。
5. 把一条已发消息编辑后重发，看历史是否正确。
6. 侧边栏：重命名 / 置顶 / 删除各做一次，刷新后看是否保留。
7. 切到英文界面再回来，看中英文是否都对。

**D 组｜C 编辑器**
1. 从示例库按"章节 → 知识点"选一个程序跑起来。
2. 写一段**故意编译不过**的代码，看报错提示是否说清哪一行。
3. 复制粘贴一大段代码（>500 行），看编辑器是否卡。
4. 用导入/导出功能各一次，确认内容没丢。
5. 从聊天里的代码块点"导入到编辑器"，确认代码一致。

**E 组｜账号 / 权限 / 边界**
1. 未登录直接访问 `/courseware`、`/classroom`、`/animation`，看是否被正确拦住。
2. 用未登录状态直接打开课件图片地址，看是否被拒。
3. 同一个账号在两个浏览器同时上课，看会不会互相覆盖进度。
4. 连续快速登录/登出 10 次，看是否被限流、是否报错。
5. 断网 10 秒再恢复，看页面是否能自愈（刷新 / 重连）。
6. 用手机浏览器（iOS Safari + 安卓 Chrome）各走一遍主要页面，看有没有布局错乱或小到看不清的字。

**F 组｜夜间模式 + 中英文（专门复现你第 9 条）**
1. 逐页切换夜间/日间：记下**哪一页、哪个元素**看不清（截图 + 页面名）。
2. 中英各走一遍：记下**没翻译**或**中英混排**的地方。
3. 夜间模式下看课堂/动画/聊天三个页面，重点看：正文对比度、按钮文字、代码块配色。

### 记录模板（每人一个表，越具体越好）

| 时间 | 我在哪一页/哪一步 | 我做了什么 | 我期望发生 | 实际发生 | 截图 | 可复现吗 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  | 每次都 / 偶尔 / 只一次 |

**规则**：一条一行；**不要合并多个问题**；"可复现吗"这一栏最重要——能稳定复现的优先修。

### 汇总与优先级规则（我这边）

1. **可稳定复现 + 影响上课** → 立刻进批次 1/2 修；
2. **可复现 + 影响观感** → 批次 3；
3. **只出现一次 / 说不清** → 先放着，等第二条类似反馈再查；
4. 每条我都会回到服务器日志与代码里找他不知道的**真因**，再决定改法。
