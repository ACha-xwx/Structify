# 部署与运维

本页是代码导航，不是对当前线上状态的认证。生产拓扑来自 [Compose](../deployment/docker-compose.production.yml)：mysql、node、spring-api、caddy。MySQL 镜像在当前文件为 8.4；发布应用镜像通过必填变量提供不可变标签。持久卷覆盖数据库、兼容服务数据、上传与代理状态，私有课程资料另行挂载。

## 配置与构建入口

- [生产环境示例](../deployment/.env.spring.example) 是变量配置入口，仅用占位符，不提交实际环境文件。
- Spring 容器构建见 [Dockerfile](../backend/spring/Dockerfile)，Node 见 [Dockerfile.node](../deployment/Dockerfile.node)。前端构建来源 frontend/package.json；代理路由见 [Caddy 配置](../deployment/Caddyfile.production)。
- prod profile 关闭 Flyway clean，启用 validate-on-migrate、禁用 baseline-on-migrate；数据库变更只能前向迁移。回滚镜像不等于可以倒退已应用数据库迁移。

## 运维脚本职责

[release.sh](../deployment/scripts/release.sh) 是发布入口，委托 deploy 并核对健康与来源；执行模式要求显式 execute/confirm。备份见 [backup.sh](../deployment/scripts/backup.sh)：说明明确默认只输出计划，执行模式包含 MySQL、Node SQLite、聊天上传及可选资料。恢复见 [restore.sh](../deployment/scripts/restore.sh)，回滚见 [rollback.sh](../deployment/scripts/rollback.sh)。健康检查见 [health-check.sh](../deployment/scripts/health-check.sh)，发布前检查见 [preflight.sh](../deployment/scripts/preflight.sh)。

这些脚本可能访问 Docker、生产数据库、文件系统或网络。本次只读其源码，不执行，包括默认计划模式；操作前必须逐一核对目标路径、环境文件、备份、镜像及对应脚本参数，不能从本文复制一个泛化生产命令直接执行。

## 本地代码沙箱

开发用 Piston 在 `http://127.0.0.1:2001/api/v2`，Compose 见 [docker-compose.sandbox-local.yml](../deployment/docker-compose.sandbox-local.yml)。仅发布到本机回环，勿把包管理 API 暴露到公网。

```powershell
docker compose -f deployment/docker-compose.sandbox-local.yml up -d
Invoke-RestMethod http://127.0.0.1:2001/api/v2/packages -Method Post -ContentType application/json -Body '{"language":"gcc","version":"10.2.0"}'
$env:PISTON_BASE_URL='http://127.0.0.1:2001/api/v2'
./scripts/start-studyroom-preview.ps1
```

重启预览前先停掉已有 Spring：两个进程不得共用同一 H2 文件。本地 `/api/v1/code/runs` 成功不证明生产 504 根因；生产上游需单独核对。历史诊断全文见 [archive/operations/local-code-sandbox.md](archive/operations/local-code-sandbox.md)。

## 私有课程资源包

课件不在 Git 中；审核后的课程包放在仓库外的 `private/`，并单独拷到生产主机。勿写入公开历史或镜像层。

生产私有根至少包含：`knowledge/`、`presentation-materials/`、`pdfs/`、`source-ppt/`、`course-content/`。前三者与 `course-content/` 以只读挂载进应用容器；`pdfs/` 作为 Node 默认 PDF 源只读挂载。Spring 的 `RESOURCE_DIR` 与此包分离，空目录在无已审资源时合法。

打包或上传前：

```powershell
$env:STRUCTIFY_REQUIRE_PRIVATE_RESOURCES = 'true'
node scripts/verify-private-resource-bundle.js
node scripts/check-ppt-offline.js
```

无 `private/` 的干净检出在未强制要求时可通过校验；生产校验必须设 `STRUCTIFY_REQUIRE_PRIVATE_RESOURCES=true`。映射表与边界见 [archive/operations/private-resource-bundle.md](archive/operations/private-resource-bundle.md)。

## 排查顺序

1. 应用不可达：区分 Vite、Caddy、Spring 的访问地址，核对端口、代理与健康检查，而不是先重置数据库。
2. 内容不能生成：核对资料路径和授权证据、模型配置、用户额度、fragment budget、job/call 状态；SENT 结果不确定时不盲目重发。
3. 代码执行失败：区分 COMPILER_NOT_CONFIGURED、上游超时、编译错误与运行错误；本地成功不证明生产上游已恢复。
4. 数据迁移失败：保留错误和当前版本，先备份再分析迁移来源；不删除 H2、不修改已应用迁移来“修好启动”。

旧生产手册与发布记录保留为[历史运维材料](archive/operations/)，涉及真实域名、历史发布信息和环境布局时以当前配置及操作环境核对。未实测备份恢复，不能承诺恢复时间或数据损失上限。
