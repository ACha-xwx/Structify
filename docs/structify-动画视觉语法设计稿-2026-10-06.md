## 一、先看别人怎么做（有依据，不是拍脑袋）

| 来源 | 结论 |
|---|---|
| **Saraiya, Shaffer, McCrickard, North（ACM SIGCSE 2004，《Effective features of algorithm visualizations》）** | **最重要的单一特征是"学习者能直接控制节奏"**；**干扰元素最少、聚焦算法逻辑步骤**的可视化对"过程理解"最好；**给一个精心准备的好例子**显著优于让学习者自己造数据。（有意思的是：伪代码显示、回看后退、引导问题**没有显著效果**。） |
| **算法可视化设计综述（中文）** | ① **增量更新**：只展示状态之间的变化，降低认知负担；② **色彩要有语义**（红=正在比较、绿=已排好、黄=正在交换）；③ **抽象层级可选**（底层指针/下标 vs 高层逻辑）；④ **与伪代码/源码同步**，把"代码"和"动作"对上；⑤ 常见做法还包括**同时显示比较次数、交换次数**等量化指标。 |
| **USF David Galles 的 Data Structure Visualizations** | 被公认为"教科书级清晰"：**极简、无冗余**，只有操作按钮 + 单步前进/后退 + 调速 + 画布缩放；每页附一句当前步骤说明。 |
| **VisuAlgo（Steven Halim）** | **"annotated states that reinforce invariants"**——状态上带标注来强化不变式；各主题视觉一致；有单步控制。 |
| **Python Tutor** | 对**指针/引用**最清楚：显式画"哪个变量指向哪个对象"。 |
| **网络可视化通用编码规则** | 重要性用**大小**、分群用**颜色（≤8–12 色）**、边权用**线宽/透明度**；**箭头必须够大**（长度 ≈ 结点半径）；标签要克制（只标最重要的 1–5%）；**避免 3D**；一致性优先。判据："**如果同事 10 秒内说不出这张图的规律，就该简化或换编码。**" |

**对我们的三条直接启示**：① 节奏控制我们已有（播放/单步/倍速/进度条）——**这是研究里最重要的一条，要保住**；② 我们缺的是**"把结构语义画出来"**（谁指向谁、当前游标在哪、哪段已处理）；③ 加东西要克制，别堆装饰。

## 二、我们现在到底画了什么（诊断，看的是引擎与播放器的实情）

**引擎每帧的数据**：`{ op, label(标题), note(一句话结论), stateSnapshot, dsvpState(状态), dsvpHighlights{nodes,edges,cells,pointers} }`。
播放器 `AnimationStage.vue`（735 行）会渲染 **panels**：`kind = tree / graph / 其它（格子）`。

| 结构 | 引擎给的数据 | 现在画出来了吗 |
|---|---|---|
| 栈 | `{kind:"stack", items:[{index,value}], **top**, metadata:{capacity}}` | **格子有，`top` 没画** |
| 队列 | `{kind:"queue", items, **front**, **rear**}` | **格子有，`front/rear` 没画** |
| 循环队列 | `{kind:"circular_queue", …front,rear,count,capacity}` | 同上 |
| 顺序表 / 排序 / 查找 | `viewState("sequence"/"sort", [row("array",arr), row("meta",{**low,mid,high,current,i,j**,operation,key})])` | **格子 + 下标有；`low/mid/high/i/j` 没画** |
| **单链表 / 双向链表** | `viewState("linked_list", [row("L", items), row("meta",{current,position,i,j})])` | **画成"一行值"**——**没有结点框、没有 next 箭头、没有 head/p 指针**；`pointers` 高亮只给了 `{role:"changed", name:"next"}`（**没有"指向哪个结点"的坐标**，所以画不出箭头） |
| 树 / 图 | `treeView(...)` 真正的 `nodes + edges(L/R)`；图有 per-node 注释（Dijkstra 的 `dist`、拓扑的 `indegree`） | ✅ **这块是对的**：层级布局、结点、边、箭头、visited、per-node 注释都有 |
| 全结构 | 每步有 `label` + `note`（播放器显示"一句话结论"） | ✅ 有（符合"annotated state"） |
| 全结构 | 无 | ❌ **没有不变式标注**（"已排序区间 [0..i)"） |
| 全结构 | 无 | ❌ **没有计数器**（比较次数/交换次数） |

**一句话诊断**：树和图是"有结构"的，**链表/数组/栈/队列是"一行值"**——`next` 指向、游标位置、已处理区间这些**语义信息全都没被画出来**，学生只能靠左边的文字去脑补。这正是"不够细致、不够形象"。

## 三、逐结构的视觉语法（建议）

> 通用规则：**颜色固定语义**（当前=强调色 / 已处理=绿 / 候选=黄 / 无关=灰），**箭头要够大**，**标签少而大（≥19px，我们的硬规矩）**，**每步只画"这一步变了什么"**（增量更新）。

### 1) 单链表（**改动最大、收益最大**）
- 结点 = **两格方框 `[data | next]`**，结点之间用**箭头**连接；`next=null` 画一个"接地"符号（⏚）而不是空白。
- **具名指针**从上方用**带标签的箭头**指向结点：`head`、`p`、`pre`、`q`、`r`（文字就是标签，不是小字注记）。
- 插入：新结点**从上方落下**，先连后继再改前驱（与文字"先接后继，再改前驱"一一对应，箭头**闪一下**表示被改）。
- 删除：被删结点**先变灰**，前驱的 next 箭头**改指向**，然后结点**淡出**。
- 循环链表：末尾结点箭头绕回 head（引擎已有自环绘制逻辑 ✓，改成结点框后复用）。

### 2) 顺序表 / 数组 / 排序 / 查找
- 每格标**下标**（已有）+ **值的格子**。
- **具名游标**画成**指向该格的带标签小箭头**：`i`、`j`、`k`、`low`、`mid`、`high`（数据已经在 `meta` 里，**只差画**）。
- **区间高亮**：已排序段用绿色底、待处理段保持普通、候选段用黄色（一眼看出"工作量在缩小"）。
- 交换：两格**先并排显示将要交换**，再落位（避免"瞬间变了"）。
- 折半查找：`low/mid/high` 三个游标 + **被排除掉的区间变灰**（这是折半"每次砍一半"的直观来源)。

### 3) 栈 / 队列（数据已有，只差画）
- 栈：画成**上开口的容器**，标 **top** 指针；入栈/出栈画元素**从上方进出**。
- 队列：画成**左右开口的容器**，标 **front / rear**；出队从 front 侧离开。
- 循环队列：画成**环形缓冲区** + front/rear/count 三个标记。
- 溢出/下溢：容器边界**闪红**（现在只有文字）。

### 4) 树（本来就对，补三处）
- **访问顺序编号**：遍历时在结点旁标 ①②③…（学生最需要的就是"谁先谁后"）。
- **子树区间**：中序遍历时标 `(左子树区间]` 这样的范围。
- 旋转（AVL/BST）：高亮**失衡结点 + 旋转轴**，并画出**旋转前后两帧**的对照（增量更新）。

### 5) 图（本来就对，补两处）
- **颜色状态**：未访问=灰、在队列/栈中=黄、已访问=绿。
- **当前边加粗**；最短路径树用**更粗的线**（dist 已有 ✓）。

### 6) 每步都要有的两条（新）
- **不变式条**：一句话写明此刻成立的性质（"已排序区间 [0..i)，a[i..n-1] 未处理"）。引擎在 `meta.invariant` 里给，播放器画在画布上方。
- **计数器**：`比较 n 次 / 交换 m 次`（研究里明确提到能培养"效率"直觉）。

### 7) 最少步数下限（你提过的"一步的演示"）
- **少于 2 步的演示不播**（或明确标注"这一步不包含过程"）。1 步的"演示"没有教学价值，还会让人以为坏了。

| 阶段 | 内容 | 为什么要这个顺序 | 触及范围 |
|---|---|---|---|
| **1** | **把引擎已经有、但没画的信息画出来**：`top / front / rear / low / mid / high / i / j / current` → 具名游标与标记；顺带给 `pointers` 补"指向哪个结点"的字段让箭头画得出来 | 数据已经在手，**纯渲染改动**，风险最低、覆盖全部数组/栈/队列动画 | 播放器为主 |

## 六、实施进度（2026-10-06 夜，本地已改、未上服务器）

> 三件事按上面的顺序都做了；**排序视觉选了"格子 + 游标 + 已排序区间"**（第 1 条的建议），
> 链表改造直接做了（第 3 条的示意图没来得及单独出，但改动可以在播放器里直接看）。

### 阶段 1：把引擎已经有、但没画的信息画出来（前端为主）

`frontend/src/animation/frame.ts`
- 新增 `FrameCursor {key,label,index}`，`FramePanel` 增加 `cursors: FrameCursor[]`。以前一帧只能有一个高亮，
  现在**每个具名指针都发布出来**：`i`、`j`、`k`、`low`、`mid`、`high`、`top`、`front`、`rear`、`current`、`pivot`…
  `focus` 保持原来的取值顺序，所以读它的代码一行没改。
- 新增 `chain: boolean`：单/双/循环链表、链式栈队列走"结点框"渲染，其它数组走格子。

`frontend/src/animation/AnimationStage.vue`
- 数组/文本面板：格子上渲染 `.cursor` 胶囊（`i`/`mid`/`top`… 用的就是教材里的名字，不翻译成"中点"），
  区间（`low..high`）用 `.cell--inRange` 描边。
- 链表家族：`.chain__node`（`[值 | next]` 两格）+ `.chain__link` 箭头，首结点标 `head`、末结点 `next` 写 `NULL`，
  具名指针悬在结点上方。

### 阶段 2：链表改成结点框 + 箭头 + 具名头指针

同上 `.chain` 那一套。逆置/插入/删除现在能看见"链接"本身，而不是一排没有名字的值。

### 阶段 3：不变式条 + 计数器

`backend/dsvp/engine/textbook-animation-engine.js`（`simulateSort`）
- **比较必须有自己的帧**。原来只有"发生交换"才报帧，所以计数器数出来是
  **冒泡排序「比较 0 次、交换 5 次」**——比不显示更误导。现在一次比较报一帧，
  发生交换时把 `swap` 动作挂在同一帧上（帧数 = 比较次数，不会因为"先比较再交换"翻倍）。
- 覆盖：冒泡、直接插入、折半插入、希尔、快速、简单选择、堆、归并（分派/收集阶段不比关键字，
  基数排序**一次关键字比较都没有**，所以它没有计数器——这是对的，也是个教学点）。
- **不变式**：每帧在 `meta.invariant` 里给一句话（"下标 0 到 i-1 是已排好的有序区……"），
  播放器画成画布上方的一条（`.stage__invariant`，19px）。

`backend/dsvp/engine/dsvp-engine.js`
- `attachCounters(steps)`：从每步已有的动作里累计 `compareCount` / `swapCount` 写回 meta。
  **只数 `compare`/`swap` 这两个含义在任何结构里都一致的动作**，所以计数器不可能声称动画没画过的事。

`frontend/src/animation/frame.ts` + `AnimationStage.vue`
- `invariant` 单独成行、**不重复成胶囊**（混在 `i`/`mid` 中间会被读成同一个层级的东西）；`比较次数/交换次数` 走胶囊。

### 怎么验的（数字都是本机实跑）

| 验的东西 | 命令 | 结果 |
|---|---|---|
| 计数器 + 排序结果 | 直接调 `simulateOperation` 10 种排序 × 3 组数据 | `[5,3,8,1]` 冒泡 **比较 6 / 交换 4**（教科书值）；`[49,…,27]` 冒泡 21/12、选择 21/6；**10 种排序末帧数组全部有序** |
| 不变式覆盖 | 同上，数带 `invariant` 的帧 | 9 种排序 **每帧都有**；归并的 `show()` 补过一次（否则 1/33） |
| 引擎自身校验 | `backend/dsvp/test/verify-*.js` | 167 能力 / 1182 步、边界探针 **13 条与基线一致** |
| 引擎契约（进 CI） | `DsvpLocalEngineTest#annotatesEverySortStepWithCursorsCountersAndWhatCurrentlyHolds` | 每帧有 invariant；4 元素冒泡末帧 6/4；比较帧同时报 i 和 j |

### 还没做

- **阶段 5**：抽象层级切换（底层指针 ↔ 高层逻辑），按上面说的先不做。

### 顺手量到的一件事：第 7 条「最少步数下限」比想的更值得做

把 167 个能力的标准例子逐个跑一遍、数 `trace.steps`：

| trace 帧数 | 个数 | 意味 |
|---|---|---|
| **1 帧** | **9 个** | `stack.initialize`、`circular_queue.initialize`、`double_stack.initialize`、`linked_queue.initialize`、`circular_linked_list.initialize`、`static_linked_list.initialize`、`union_find.initialize`、`hash_function.division_remainder`、`hash_function.pseudo_random` —— **引擎一个过程帧都没有**，播放器只能走 `查看结果` 兜底 |
| 2 帧 | 2 个 | `linked_list.initialize`（建立头结点）、`hash_function.mid_square`（取平方值中间若干位） |

也就是说有 9 个能力点出来的"动画"**从头到尾只有一帧**，学生点「下一步」什么都不会变——
这正是"看着像坏了"。按第 7 条做（不播，或明确写"这一步只有结果、没有过程"）能直接消掉这 9 个；
本轮**只量了、没改**。
