# Studyroom 开发测试数据与课件方案

## 目标

在不放宽课程证据校验、不加入通用知识兜底的前提下，让开发环境能够完整演示 Studyroom：使用真实的大模型与现有课堂 API，以可明确识别的模拟知识数据支撑检索；将实际已有 PPT 转成 WebP，并为缺失的演示资源准备 Mock。开发与上线共用同一套服务逻辑，环境之间仅数据和资源配置不同。

## 当前情况

- Studyroom 在检索不到授权课程证据时会返回 `STUDYROOM_EVIDENCE_UNAVAILABLE`。该保护保持不变。
- 教材导入器要求原始来源、页码、哈希和 PDF 核验信息。模拟知识不得伪装成经过真实教材核验的数据，也不应通过修改导入器来绕过校验。
- 当前前端 Mock 资源只有一组栈主题 SVG、动画和 C 示例；它会覆盖课堂步骤的资源展示，因而可能把二叉树问题展示成栈资源。
- 仓库有 22 份原始 PPTX，涉及第 1、2、3、5、6、7、8、9 章；当前源 PPT 未覆盖第 4 章和第 10 章。
- 现有课件服务支持 PNG 页面及其同名 WebP 孪生，若 WebP 存在会优先使用。产物应位于私有课件目录，不应打进前端公开静态目录。

## 已完成的 PPT 转换

- 2026-10-12 已将 22 份源 PPTX 逐页导出为 PNG，再按 WebP quality 80 编码；按页面宽高比统一渲染为 1080px 高。
- 共转换 1,210 页；PNG 共约 196 MiB，WebP 共约 76 MiB，减少约 61%。抽查二叉树课件页面，图文显示正常。
- 源 PPTX 未修改；PNG 保留为 WebP 孪生和课件服务的源图。输出位于被 Git 忽略的 `presentation-materials/rendered/` 私有目录。
- 页面图像已经生成，但还没有生成 `slides.json`、课时计划及页面标注索引。因此现阶段是转换产物，不表示它们已出现在 Studyroom 页面；接入时需生成/配置这些索引，并使用现有课件 API。

## 设计

### 1. 模拟知识数据

- 为当前课程的 10 个章节准备小规模、可追溯的开发测试知识条目，覆盖定义、关键性质、常用操作、复杂度、典型例题和易错点。
- 条目标题、来源标识和 UI 引用均带“开发模拟”标记；不填写虚构的教材页码或 PDF 核验结论。
- 模拟数据只注入开发测试数据库，生产知识库不包含这些条目。实现采用数据夹具，不改 Studyroom Graph、检索服务、证据校验和模型提示词。
- 提问仍经过现有授权过滤、证据检索、资源候选校验、模型生成和来源校验。没有匹配夹具的提问仍拒答，不转为通用知识回答。

### 2. PPT 页面

- 使用 `course-assets/source-ppt/` 中的原始 PPTX，不以示意 SVG 替代已存在的课件。
- 保留原 PPTX 不变；逐页导出为 PNG 中间图，再用现有 WebP 转换流程生成同路径、同页序的 `.webp`。
- WebP 放在 `presentation-materials/rendered/` 的私有课件目录，与 PNG 页面及课件索引元数据配套；由现有 `PresentationCatalog` 解析并提供图片 URL。不得把整套课件复制进 `frontend/public/`。
- 为页面生成稳定 slide ID 和章节/课时映射。初次接入的 22 份 PPT 只覆盖第 1、2、3、5、6、7、8、9 章；第 4、10 章没有原始 PPT 时显示资源缺失状态，不拿其他章节的页面冒充。
- PPT 画面本身为真实原版内容。开发 UI 可标记“原版课件”，只有尚无来源的动画、C 示例或页面才标“模拟资源”。

### 3. 动画与 C 示例

- 静态动画定义和 C 示例作为开发 Mock 数据，按章节及学习步骤匹配，避免跨主题资源错配。
- C 编辑器仍调用真实代码运行 API；仅示例代码和预期输入输出使用开发夹具。
- 动画模拟资源使用真实动画播放器渲染；没有对应夹具时展示资源缺失，不静默复用不相关动画。

### 4. 流程

```text
首问
  → 现有 Studyroom API
  → 现有课程授权与证据检索（开发库命中带标记的 Mock 知识）
  → 现有模型生成大纲和讲解
  → 现有证据/资源候选校验
  → 步骤按主题绑定资源
       ├─ 原版 PPT：私有 PNG + WebP 孪生，经现有课件服务读取
       ├─ 动画：开发 Mock 定义，经现有播放器展示
       └─ C：开发 Mock 样例，经真实代码运行接口执行
  → 追问沿用同一课堂；追加讲解仍需检索到证据
```

## 方案比较

| 方案 | 优点 | 风险 / 代价 | 结论 |
| --- | --- | --- | --- |
| 开发数据库注入明确标识的知识夹具，静态资源按主题提供夹具 | 使用同一 API、检索和模型路径；开发与生产的差异仅为数据 | 需要维护隔离的开发数据与资源索引 | **采用** |
| 让无证据请求直接使用通用模型知识 | 启动最快 | 绕过课程证据要求，结果无来源保障 | 不采用 |
| 把模拟文本伪装成教材核验内容导入 | 可复用当前教材文件目录 | 虚构页码/核验记录，破坏来源可信度 | 不采用 |

## 验收标准

1. 开发环境对 10 个章节的代表性问题均能从明确标记为 Mock 的资料中检索到证据；引用可以看出是开发模拟资料。
2. 对模拟数据未覆盖的问题，仍返回无授权课程资料；没有启用通用知识兜底。
3. 原始 PPTX 未被改写；已提供的 22 份 PPT 每页均有 WebP 产物，并与 PNG/slide ID/章节映射一致。
4. 第 4、10 章缺少源 PPT 时显示清楚的缺失状态，不出现其他章节的课件。
5. 10 个章节的动画和 C 示例按主题绑定；生产入口不读取开发 Mock 知识或资源。
6. C 示例通过真实代码运行接口执行；模型调用、会话、追问、授权和配额逻辑保持真实。

## 风险与边界

- 当前 PPT 源文件不包含第 4、10 章；这两章的 PPT 需要后续补充，暂不构造假原版页面。
- WebP 只是页面图像格式，不替代 PPTX 原件或 slide 索引；图片产物需与现有课件 catalog 元数据一并部署。
- Mock 知识仅用于开发验收，不能作为教学内容或生产知识来源。
- 实现进度及真实服务验证记录见下一节。

- 演示入口 `/studyroom-demo` 使用真实创建、恢复、追问及进度 API。首问章节为空时，按步骤的开发资料证据 ID 或明确主题选择资源；搜索对应章节全部 deck 的真实标题和文字。没有匹配时显示资源缺失。

- 课件图片加载失败显示明确提示；动画切换回来可以重新加载，较早的资源加载响应不会覆盖当前选择。

### 生成课件索引

在项目根目录执行：

```powershell
pwsh -NoProfile -File scripts/build-studyroom-presentation-index.ps1 `
  -RenderRoot presentation-materials/rendered `
  -SourceRoot course-assets/source-ppt
pwsh -NoProfile -File scripts/test-studyroom-presentation-index.ps1
```

生成的两个 JSON 与图片一起保留在被 Git 忽略的私有目录。`SourceRoot` 模式检查源文件、页数及连续页序；检查失败时保留现有索引。
