# Structify 课堂与动画检查报告

检查日期：2026-09-15  
唯一目标：`https://github.com/ACha-xwx/Structify.git`  
本地基线：`d99a8fbbf6f892c1744e25bf4af2ea9a7fd35aa2`  
范围：检查现有 Vue 前端、Spring 课堂与动画后端、相关契约和测试。没有修改业务源码、推送或部署，没有使用旧 8793 页面作为验证对象。

## 结论

现有项目并非没有功能，而是“固定教学示例、真实课堂会话、动画协议适配、前端播放”没有完整串起来。部分缺陷是接口字段不一致，另一些是课堂执行模型和算法执行本身缺失。只改接口地址不能解决，也没有必要先重做页面布局。

## 验证边界

- 原有 Vue 测试：66 个文件、407 项测试通过。
- Vue 生产构建：通过，包含 TypeScript 检查；有大于 500 kB 的 JS 分包警告，非本轮核心故障。
- 额外本地诊断：6 项成功复现现存缺陷。这些测试断言的是缺陷现状，不代表功能验收通过。文件位于被忽略的 `frontend/src/tmp-audit/diagnosis.spec.ts`。
- 尝试运行 Spring 的课堂与 DSVP 单元测试，Maven wrapper 下载收到 HTTP 403，未进入 Java 测试阶段。因此下列 Spring 结论标为源码确认，不宣称真实接口联调已通过。
- 没有读取生产数据库、调用生产模型、测试线上站点。线上是否已经发布课堂脚本、模型配置是否可用仍待后续验证。

## 1. 课堂首要问题：完整脚本被压缩，同类型后续步骤无法执行（P1，源码确认）

位置：`backend/spring/src/main/java/com/feng/dsagent/classroom/ClassroomScriptParser.java:63–105`、`:202`；`ClassroomScriptPlan.java`；`ClassroomStateMachine.java`。

- `steps` 被读取并验证，但最终只保存各固定阶段的一条内容。
- explain、question、discussion、blackboard、summary 都只选第一条；固定状态转换不维护原始步骤游标。
- 例如“讲解 A → 提问 A → 动画 A → 讲解 B → 提问 B”无法完整按脚本执行，后面的同类内容不会进入课堂展示。
- 因此，即使将更多完整教案放入数据库，也不会自动变成完整课堂。

修复方向：保留完整 steps 序列，以会话中的步骤游标和交互状态推进；暂停、恢复、手动下一步依附该序列。

## 2. 课堂中的动画/课件引用未真正被页面消费（P1，源码确认）

位置：`frontend/src/user/views/ClassroomView.vue:178–197`、`:269`、`:403`；`frontend/src/user/views/AnimationView.vue:362–372`；`frontend/src/user/adapters/algorithm-stage.ts:126–136`。

- 后端支持 `animationRef`，也接受 `contentRef`、`codeRef`。
- 课堂页面按键值显示 stage，对象被 JSON 序列化成文字；没有将这些引用解析成对应播放任务。
- “查看算法舞台”只传章节、课时、会话 ID，没有传当前步骤的动画引用或请求。
- 动画页首开必定从章节对应的本地 fixture 取场景，不会读取该课堂步骤的动画请求。
- 后端的 `/animations/generate` 在用户侧有 API 包装，但在检查到的用户业务页面中没有实际调用点。

结果：有课堂脚本、有动画 API、有展示页面，但上课讲到某个具体例子时，演示并不自动使用那个例子。

## 3. 当前判答不是语义理解，也没有课堂插问路径（P1，源码确认及诊断复现）

位置：`ClassroomAnswerEvaluator.java:44`；`frontend/src/user/fixtures/classroom-preview.ts:391–456`；`ClassroomService.java:62–84`；`ClassroomStateMachine.java:46–57`。

- 正式课堂通过规范化字符串后逐字相等来匹配预期答案，正确的同义表达可能被判错。
- 大多数本地课堂示例把任意非空答案标为 CORRECT。
- 顺序表示例用 `/尾|后|覆盖|右移/` 判定，包含否定意义的错误回答也可能被判对。
- 诊断实际复现：“完全无关的答案 abcxyz”被通用示例判对；“不需要从尾部移动，直接覆盖即可”被顺序表示例判对。
- 当前课堂动作只有 ANSWER、PAUSE、RESUME、CONTINUE、FINISH；ANSWER 仅在 WAITING 接受，没有独立的学生插问、老师回答、返回原讲课位置的流程。

这与用户要求“语义识别使用大模型”冲突。字符串规范化本身不是问题，使用它代替语义判答才是问题。

## 4. 前端按钮与课堂状态机不一致，示例本身还会循环（P1，诊断复现及源码确认）

位置：`ClassroomView.vue:196–203`；`ClassroomStateMachine.java:34、66`；`classroom-preview.ts:414、456`。

- WAITING 显示 CONTINUE，但服务端明确要求先 ANSWER，点击会返回状态冲突。
- SUMMARY 仍显示 PAUSE，但服务端已禁止对结束课堂操作。
- 本地示例进入 DISCUSS 后，再点 CONTINUE 仍是 DISCUSS；诊断连续点击 10 次依然如此，只能显式点击 FINISH 结束。

## 5. 自定义动画缺少必需参数，部分菜单操作服务端不支持（P1，源码确认及诊断复现）

位置：`AnimationView.vue:83、303–316、333–337`；`DsvpAnimationAdapter.java:39–49、153–178`。

- 表单只有初始数据、操作值，构造的 params 主要是 capacity/value。
- 默认顺序表示例原本指定 index=2，重新提交自定义操作时 index 丢失。诊断已经复现这一点。
- 数组交换缺 i/j；哈希操作缺 key/val；链表 find 连 value 都不发送；插入、删除无法明确位置。
- 合并接口需要两个数组，但逗号切分输入只能得到扁平列表，无法表达它要求的输入结构。
- 前端提供 tree/traverse、graph/dijkstra、graph/highlight，服务端对应白名单不支持这些组合。

结果：部分操作必然报协议错误，另一些使用默认位置，无法按用户指定含义运行。

## 6. 服务端 DSVP 适配器不是完整的算法模拟器（P1，源码确认）

位置：`DsvpAnimationAdapter.java:133–150、179–191、287–313`；`AnimationValidator.java`。

- 顺序表 merge 实际是把右表逐项插到左表末尾，没有比较两个表的当前元素。
- 用仓库自身示例 `[[1,3],[2,4]]` 推导，输出操作会得到 `[1,3,2,4]`，不是有序归并结果 `[1,2,3,4]`。
- 右表超过 20 项时只生成前 20 项操作，存在静默截断。
- 图 BFS/DFS 被映射成单条 highlight，没有计算遍历队列、栈、邻接关系和访问顺序。
- 其他大多数操作只返回一条操作描述，trace 没有逐步状态快照。
- AnimationValidator 主要验证字段、类型、长度与操作白名单，不验证完整执行后是否保持堆序、不丢数据、得到正确遍历结果等算法不变式。

不能把“返回合法 JSON”作为“算法执行正确”的验收标准。

## 7. 动画页面的播放逻辑与数据结构语义不一致（P1，源码确认）

位置：`AnimationView.vue:95–98、123、271、305–315、398–404`。

- 页面自行回放数组增删改，并未用服务端 trace 的状态快照驱动。
- 堆 insert 当作普通追加，extract 当作数组删除，没有上浮/下沉；哈希 put/get 没有对应的状态更新逻辑。
- node 字段没有用于访问指针；缺少 index 时指针默认落在下标 2，可能与实际访问节点无关。
- 树和图的连线使用固定 SVG，不随真实关系生成；真实 graph 响应又被后端映射为 tree，页面可能按树展示图。

结果：节点可以动、步骤文字可以变，但不能保证画面反映真实算法状态。

## 8. 预览机制让“看得到内容”不等于“真实链路已接通”（P2，源码确认及诊断复现）

位置：`frontend/src/user/adapters/classroom.ts:49–67`；`algorithm-stage.ts:105–136`；`fixtures/algorithm-stage.ts:519–522`。

- 游客课堂不调用脚本接口；已登录用户遇到空目录或部分服务不可用错误，也会转本地示例。
- 动画首开始终本地预览；服务不可用时可以回退固定示例，而不是此次自定义请求的计算结果。
- 未匹配到的课时会回退顺序表插入，诊断已复现。
- 页面确实有“示例预览”等提示，不是完全没有标识；问题在于预览路径不能替代真实服务验收，也不能代表全部课时已接入。
- 已登录用户从本地预览课堂打开自定义动画，会携带预览会话 ID；服务端要求该课堂会话在数据库中属于当前用户，该路径还存在上下文校验冲突。

## 9. 测试通过没有覆盖上述教学正确性（P2，源码确认）

- Vue 原测试主要验证界面、mock 响应、来源提示与基础事件调用，没有验证完整课堂脚本和真实算法最终状态。
- Spring DSVP 样例测试检查协议、trace_id、结构合法性，没有断言归并后的完整有序结果。
- 根目录与 frontend、Spring 有不同测试入口；根目录旧 HTML/Node 静态校验不能替代 Vue → Spring 的端到端验证。

## 后续处理顺序

1. 保留现有布局，先明确真实课堂与预览的入口和数据边界。
2. 修完整脚本步骤游标、合法按钮、独立插问与大模型语义判答。
3. 将当前课堂步骤的动画引用接到演示请求，不再只传章节后展示另一份固定示例。
4. 对齐操作白名单、必需参数与错误返回；实现实际算法模拟和逐步状态数据，前端只负责显示它们。
5. 增加整课走通、插问恢复、有序合并保留重复值、树图遍历、堆序、哈希更新等正确性测试，再做实际服务联调。

本次没有实施上述修复；仅输出问题、诊断证据与后续顺序。
