# 课程问答三档深度与大纲协商设计

日期：2026-10-18。状态：产品主流程已确认，本文待审阅。默认档位为系统学习。

## 目标与依据

将课程问答从直接生成课堂改为：提出问题 → 选择深度 → 生成并审阅大纲 → 与 AI 修改 → 确认开始 → 按单元生成、讲解与练习。学生决定学习范围，系统负责知识覆盖、材料匹配及确认后的履约。

当前创建接口直接生成并保存完整课堂，没有独立草稿、深度选择或确认状态。已检查的“栈的知识有哪些”课堂包含四个 PPT 步骤和一个文字检查步骤；每步有动画和代码候选，但均未选。首次绑定因场景边界校验失败后，旧修复提示要求每步最多一个资源，并在修复后关闭代码选择要求，造成生成结果收缩。不能将这次现象概括为资源目录中没有动画或代码，也不能从候选数量推断候选一定相关。

本设计延续已实现的按需场景、多页课件、代码讲解/实验及授权机制，保留用户认可的课堂展示区。新工作集中在进入课堂之前的规划，以及确认后的生成与质量保证。已有测试证明工程路径可运行，教学质量仍需自然提问和真实模型验收。

## 三档学习深度

- 快速了解：掌握核心概念、知识结构、必要例子及典型用途；实现细节和实验默认列为可选拓展。
- 系统学习：默认档位。覆盖所选主题的主要知识、必要过程演示、实现讲解、关键边界与理解检查。
- 深入掌握：在系统学习上增加实现比较、复杂度推理、错误诊断、变式及实验。详细程度受主题、学生基础和明确排除项共同约束。

深度改变教学目标的范围和展开程度，不只改变字数。三档不固定步骤数，不要求每步配齐资源，也不规定每堂课必须有动画或代码。例如学生明确“不涉及编程”，深入档仍应遵守这一限制，并在大纲标明实现部分未纳入。

宽泛问题使用学习单元组织主题，每个单元再包含教学步骤；单点问题可以只包含一个单元。深度、单元和步骤是不同层级，不能把五个笼统标题当作完整课程，也不能用重复步骤凑数量。预估时长仅作为可调整的粗略区间，缺少依据时不显示精确分钟数或生成耗时承诺。

## 大纲审阅与协商

入口在问题输入附近提供三档名称、简短说明和默认选中态，首要操作为“生成学习大纲”。生成前可查看、修改问题及明确的学习约束。

大纲页包含：本次目标与深度、建议先修知识、各单元及目标、计划覆盖的知识点、展开程度、计划材料及教学用途、检查或练习方式、未覆盖内容和资源缺口。每个单元均有稳定标识，便于局部修改和后续追踪。

大纲阶段只做知识检索、规划和材料可行性检查，不生成完整讲稿、逐页正文或完整实验讲解，不自动进入课堂。展示的页数、材料名称或代码示例只有在已核验时才能标为可用；尚未确定的内容标为计划或待匹配。

学生可以通过自然语言增加、删除、简化、展开或调整单元顺序，例如“顺序栈详细讲，链栈带过，不学表达式求值”。AI 根据原大纲和修改意见生成新版本，保留未受影响的单元标识与内容，展示新增、删除、调整范围及顺序的摘要。若意见无法同时满足，说明冲突并保留原版供继续修改，不自行舍弃学生要求。

切换档位也生成新版大纲及差异，不能视为已确认。页面保存大纲版本和修改对话，支持刷新后继续审阅，并允许查看上一版、恢复为新的草稿版本。失败的修改请求不覆盖最后一份有效大纲。

唯一进入新课堂正文生成的操作是“确认大纲，开始学习”。按钮提交当前可见版本；存在尚未完成的大纲修改、过期版本或未解决的必要资源缺口时不能确认。资源可选项缺失不阻止确认，但必须明确显示。

## 知识覆盖规划

引入经过审核的主题知识框架，包含知识点、先修关系、教学作用、深度建议和边界主题。框架用于覆盖检查和生成参考，不是所有学生固定走完的课程模板。框架版本随大纲保存，学生明确删减的内容不再作为遗漏强行补回。

首批为栈、队列、二叉树建立框架，用于验收宽泛问题。其他主题继续基于授权资料生成，并诚实标注尚未通过主题框架完整性检查，不宣称全课程已经审核完备。新增框架通过课程数据维护，不依赖在提示词中不断堆叠关键词。

“栈的知识有哪些”的系统学习初稿应考虑：定义与后进先出；基本操作及状态变化；顺序栈；链栈及二者比较；空满、上溢下溢及复杂度；典型应用；系统调用栈与递归；理解检查与必要实验。多链栈等拓展单列，由学生取舍。若实现、应用内容过多，拆成能独立讲清的目标，不用一张局部课件支撑整个大目标。

知识完整性按已选择的范围判断，不以覆盖整套教材或展示全部课件作为标准。快速了解可以主动缩小范围，但不能把省略细节描述成已经讲解完成。

## 资源的教学职责与承诺

每个目标先声明教学活动和必要材料能力，再选择具体资源。定义与结构对照适合文字/课件；状态变化适合动画；实现机制适合真实源码；修改、调试、边界验证适合实验；检查理解采用提问或练习。资源仍分主场景与必要补充场景。

材料需求分必要、建议、可选，并记录用途。例如已确认目标是观察栈顶变化，匹配动画应被认真选择；若学生确认的是阅读概念总览，则无需强制播放。实现目标存在直接匹配源码时，不能用结构图代替代码；无匹配源码时应在确认前说明并调整目标，不能塞入不相关示例。

课件检索从高相关单页升级为按目标选择页组。页组使用已有页引用，补充定义、图示、操作、实现、例题、总结等教学角色。缺少角色元数据时依据已提取正文形成候选建议，不能把模型猜测当作审核事实。按需补全材料或拆分目标，不默认附上整套课件。

大纲保存已核验材料的引用和需求快照；确认后再次校验权限与可用性。允许在同目标、同能力内选择更合适的已授权等效材料，并记录变化；必要材料类型、目标或范围发生变化时需回到大纲审阅，不能悄悄把动画/代码承诺降为文字。

编译服务未配置与源码不可用分开处理。代码讲解仍可准备；必须运行才能完成的实验在大纲中标记执行服务缺口。学生可以先配置服务，或明确改为预测、阅读等可完成活动后重新确认，不展示虚假的运行通过状态。

## 确认与按单元生成

大纲草稿、确认记录和课堂运行内容分开持久化。确认记录绑定不可变的 outlineRevision、深度、范围、单元目标及必要材料要求，版本含义与现有 room.version 并发版本、场景 schemaVersion 分离。

确认后优先生成首个单元；首单元可用即可进入学习。后续按单元准备，默认只预取下一单元，其余在学生选择或继续学习时生成，避免学生离开后仍无界生成整堂课。界面区分未准备、准备中、可学习、待重试，不用虚构百分比表示模型生成进度。

单元生成是可恢复任务，状态及结果写入数据库，使用唯一任务键避免刷新、双击或重试重复调用和重复计费。进程中断后能按任务租约恢复，不只依赖内存线程。每次真实模型调用仍经现有配额边界，规划、修改、正文与修复使用明确的操作标识。

正文必须兑现已确认单元目标，不允许生成器擅自减少知识点、把未确认拓展加入必学部分，或改变学生的排除项。课程范围大时按目标拆分任务和输出预算，不用一个整堂课 JSON 承载深入档全部内容。

格式可确定修复时由程序归一化。模型修复只针对失败步骤，携带原目标、有效结果及具体错误；单步最多一次模型修复，之后保留失败状态并提供重试或修改大纲。权限和材料边界错误不能通过放宽白名单解决；修复后继续执行与首次相同的教学检查。其他通过的步骤不能被整堂课重生成覆盖。

进入课堂后可随时查看确认的大纲。修改范围创建独立草稿，在重新确认前保留当前课堂可读内容；新草稿不会自动开始正文生成。重新确认后仅复用目标和材料要求未变且仍有权限的单元，其余单元重新准备。旧版本后台结果不得写入新版本；新确认操作使旧版本未完成任务失效。

## 两道质量检查

大纲确认前检查：所选范围的覆盖、先修与顺序、目标粒度、档位一致性、明确排除项、资源可行性及学生修改意见的落实。遗漏必要目标、资源缺口或要求冲突作为具体问题返回，学生可调整范围后再审阅。

单元交付前检查：已确认目标是否兑现、材料是否足够支撑讲解、源码函数与输入是否真实对应、动画是否表达所需状态变化、逐页说明是否对应页面、修复是否丢失承诺。结构合法与教学合格分别记录，不能因 JSON 解析成功就认定课堂质量通过。

确定性规则检查版本、引用、权限、参数、结构和承诺；语义检查基于知识框架、范围、步骤与材料核对，模型判断只作有证据的辅助，不作为唯一安全门。检查不通过必须给出具体目标或材料原因，不能用主观分数代替说明。

## 边界、兼容与职责

大纲规划、修改、覆盖检查、材料可行性、确认、单元生成及交付检查各有独立职责；现有 StudyroomGraph 作为调度入口逐步拆分，不继续将所有提示、版本和后台任务规则堆在同一个类。复用资源目录、场景渲染、代码沙箱及配额设施，不重做已经满意的展示区。

所有草稿、版本、确认和生成任务均校验用户所有权。客户端只能确认准确版本，不能用自行提交的大纲 JSON 绕过服务端校验；课程资料、修改意见和运行输出一律作为不可信数据处理。

已有课堂继续正常阅读与追问，不要求重新确认；学生主动选择重新规划时才进入新流程。新的首次提问一律经过深度与大纲审阅，不能经旧创建接口绕过确认。旧客户端的写入兼容方式在实施计划中明确，原则是给出升级提示而非后台替学生确认。数据库使用新增迁移，不修改已执行迁移。

## 验收与发布顺序

第一部分交付三档、大纲草稿/修改/确认、版本归属、按单元生成和原有修复退化修正。第二部分接入首批知识框架、教学资源职责及两道质量检查。两部分构成同一产品闭环；在覆盖规则接入前，不对外宣称完整教学质量能力已完成。

验收以自然问题为主，并覆盖明确需求和反例：

- 同问“栈的知识有哪些”，三档在覆盖与展开程度上有实质差异，不只是同五个标题变长。
- 学生确认前不产生正文任务；修改和切换深度后必须确认最新可见大纲。
- “顺序栈详细讲，链栈简单带过，不学表达式求值”在大纲与正文中持续有效。
- 系统学习的操作过程安排匹配演示，已有相关源码的实现目标绑定正确代码；不以凑资源数量验收。
- 多页课件足以支撑目标，局部多链栈页面不能代表整个顺序栈/链栈实现单元。
- 增加一个实验时不自动膨胀为多个准备步骤；无沙箱时明确执行限制。
- 首单元可学时其他单元可以尚未准备，页面如实呈现状态；刷新或重复确认不重复生成和扣费。
- 人为制造单步输出、材料或格式错误，仅修复该步，不删除目标、代码或动画；失败仍保留其余已准备单元。
- 权限撤销、版本竞争、旧任务晚返回、服务重启及旧课堂读取都有明确的正确结果。

使用固定授权目录和模型响应夹具验证状态、版本、覆盖、幂等及降级；用真实模型对栈、队列、二叉树的宽泛问题分别验证三档，并复查修复前后差异。自动测试和教学人工验收分别报告，少量成功样本不宣称稳定成功率。浏览器检查入口、大纲修改与差异、确认、单元准备状态、课堂回看及窄屏操作。实施过程中保护当前工作区既有改动，只提交可安全划分的本次内容。

## 审阅结论

本设计覆盖已确认的三档默认、学生审阅与自然语言修改、确认后按单元生成，并将知识覆盖、资源适配、质量检查和修复退化治理纳入同一流程。未增加自动讲述、区域高亮、多角色讨论或自由编辑全部材料等无关范围。设计文档审阅通过后编写实施计划，再进入编码。
