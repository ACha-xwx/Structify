# H. 仅为开发账号豁免每日额度而保留工作流约束

## Context（背景）

工作区需要指定开发账号持续调试，现有每日额度可能限制该用途。代码不能证明这是一项长期团队政策，也不能证明为何需要默认开启。此记录暂存环境隔离与额度边界，是否值得长期作为独立 ADR 待确认。

## Decision（决策）

只有 dev profile、显式启用策略及匹配配置账号共同成立时，豁免用户每日额度容量检查并暴露相应状态。仍保留调用账本；未改 fragment 的修订预算机制，不能把用户额度豁免解释为工作流无限调用、无限并发或免供应商计费。不得将开发特例无条件扩展到生产。

## Considered Options（考虑过的方案）

未找到历史备选方案记录。事后分析的可能替代方案：临时提高每日额度，或完全使用确定性替身，分别保留额度上限或无法覆盖真实模型交互；不代表团队已经比较并排除它们。

## Consequences（影响与约束）

正面：开发例外限定在环境与身份组合，不必整体移除额度控制。

代价：特殊路径增加理解和测试成本；真实模型费用仍存在。

新增约束：测试须覆盖非 dev、开关关闭、账号不匹配及工作流预算仍有效；文档和 API 不能把额度剩余量误解释成有限数。

风险与后续：默认启用范围及长期治理未确认。如果只是临时调试，本记录应在确认后降为开发说明，并在索引标明撤回，不继续扩展为架构决策。
